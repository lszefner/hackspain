Albertito · plan del frontend

Next.js (App Router, TS, Tailwind) · español · mock data primero, contrato de datos = esquema de alberto.db. Cada página compra puntos concretos de la rúbrica (100 + 10).

La tesis del producto

No es «un dashboard del pipeline»: es la ficha y el escritorio de un trabajador digital. Albertito es un empleado con un puesto, un manual (norma_v3.yaml), unos límites declarados (qué NO hace) y un parte de trabajo. Alberto (el humano) supervisa, resuelve escalados y le actualiza el manual — nunca el código. Toda pantalla responde a una de tres preguntas del jurado: ¿qué decidió?, ¿por qué exactamente?, ¿qué pasa cuando algo cambia o falla?

/expediente/[fileId] — Seguir UNA decisión

La proyección de alberto explica: input → estado → evidencia → reglas → resultado. Es la página que se enseña al tribunal.

  • Cadena de custodia: PDF (visor embebido) → sha256 → ingesta → extracción (vía, latencia, coste, ¿cuadra la aritmética?) → decisión.
  • Veredicto de cada regla con su evidencia literal (IBAN factura vs IBAN maestro, importe vs ERP…), en verde/ámbar/rojo.
  • Versiones: norma, snapshot ERP, snapshot maestro con los que se decidió. Si existe una decisión v4, se muestra el diff aquí mismo.
  • Notas de Alberto solo si aplican a este proveedor/pedido/regla. Timeline de eventos y reintentos. Navegación prev/next dentro del filtro activo.

Arquitectura del frontend

frontend/ (Next.js 15 · App Router · TypeScript · Tailwind) ├── src/app/ │ ├── page.tsx → / muro + KPIs + ficha │ ├── expediente/[fileId]/page.tsx → /expediente traza completa │ ├── bandeja/page.tsx → /bandeja escalados + redactor │ └── operacion/page.tsx → /operacion coste · diff · salud ├── src/lib/ │ ├── types.ts ← espejo 1:1 del esquema SQLite (documentos, decisiones, │ │ extracciones, eventos, resoluciones, notas, reglas) │ ├── data.ts ← interfaz DataSource: LA COSTURA. Hoy mock, mañana │ │ better-sqlite3 sobre alberto.db o fetch al FastAPI. │ └── mock/ ← fixtures realistas generados con el reparto real │ (431/49/20, motivos y cifras del TODO.md) └── src/components/ ← Muro, Kpi, Regla, Timeline, FichaAlbertito, …
Decisión clave (candidata a ADR): las páginas consumen únicamente src/lib/data.ts. Los tipos calcan las tablas reales (doc_id, norma_version, snapshot_erp, snapshot_maestro, reglas_json…), de modo que enchufar la BD real es implementar una segunda DataSource, sin tocar ninguna vista.
