# Working rules

- Never read `.env`; contextual review takes explicit configuration and does not load dotenv.
- Install the repository decision/review path with `uv sync --locked --extra worker --extra backend`.
- Task 3 focused checks: `uv run --locked --extra worker --extra backend python -m pytest -q tests/test_contextual_review.py tests/test_contextual_provider.py`.
- Task 1 integration regression checks: add `tests/decision_context` to that pytest command. Its Postgres tests use a disposable local instance and skip when the required binaries are unavailable.
- Lint new review code with `uv run --locked --extra worker --extra backend ruff check ingestion/contextual_prompt.py rules_ingestion/contextual*.py tests/test_contextual_review.py tests/test_contextual_provider.py`.
- Tests must not call paid APIs or shared databases. Scripted review fixtures are contract tests, not measured LLM accuracy.
- Keep `evaluation-result/1` immutable. Confirmed submitted/processed database duplicates reject; do not call them paid without payment evidence. Review artifacts never authorize payment.
- `rules_ingestion` is a repository API, not included in the ingestion wheel. Task 3 is not wired into the frontend.
- `benchmark/schemas` is the extraction schema source of truth; packaged wheels carry copies under `ingestion/schemas`. Do not edit benchmark code/references/reports, existing provider prompts, or pipeline/config settings unless the task requires it.
- For packaging-only changes, refresh the lockfile with `uv lock --offline` without upgrading dependencies.
- The canonical end-to-end backend is `python -m backend.run_revision invoice.pdf --request-key INTENT --evaluation-date YYYY-MM-DD --input-dir PDF_DIR --sources SOURCES_YAML`. It requires Supabase, reuses stored rules by exact generation inputs (generates only on a cache miss), then runs persisted extraction, the v2 evaluator, and contextual review by default. `REVISION_REVIEW_ENABLED=false` explicitly disables review and uses the evaluator's output, including PAGAR; persist this policy and show DISABLED, never a fabricated review. `backend.server` uses this same path and Postgres results; no SQLite fallback. The lower-level `InvoiceDecisionEngine` API can evaluate/review already-persisted extractions separately.
- `REVISION_JSON_STORAGE=postgres` stores canonical audit JSON transactionally in existing artifact rows with explicit `postgres/` addresses; original/source bytes stay in private Storage. Both historical and compact artifacts must remain readable. Complete ERP snapshots may be reused for at most 30 seconds, retaining their original capture timestamp. `REVISION_RULESET_RUN_KEY` explicitly pins an existing completed run's rules and audit, requiring exact workbook/mapping/profile identity. See `docs/revision-fast-path.md` for measured warm/cold timings.
- `GET /api/factura/{file_id}/flujo` (`backend/flujo.py`) projects one invoice's full stored flow: identity, frozen run input, extraction route with `por_que_vision` gaps, every job/attempt, parsed invoice, evaluation, review, deliverable `salida` via `export_outcomes.decide_output`, and explicit `no_registrada` resolution/payment stages. It is read-only: never recompute rules or call providers there; sections degrade to an `error` entry when an artifact is missing.
- Core CLI: `python -m rules_ingestion.engine_cli evaluate --input-id UUID --interpreter deepseek --ruleset PATH --rule-source NAME=PATH --snapshots PATH --evaluation-date YYYY-MM-DD --captured-at TIMESTAMP`; repeat `--rule-source` for every original XLSX/CSV/profile/mapping input. Source lineage is caller-attested, not proof of which historical bytes generated an existing ruleset.
- Core review CLI: `python -m rules_ingestion.engine_cli review --record-id er_HASH --request-key INTENT --reviewed-at TIMESTAMP [--endpoint HTTPS_URL] [--model MODEL]` reviews with the Helmcode configuration; `--endpoint`/`--model` and `REVIEW_API_KEY` override it for a different model or account. Reusing an intent cannot repeat an in-flight/unknown provider call; a new key is an explicit new attempt. `show --record-id er_HASH` verifies saved records without paid calls.
- Core persistence requires the `core_engine_records` migration, Postgres credentials and a private Supabase Storage bucket; no local fallback. Migration/backfill against shared systems needs separate approval. Snapshots remain explicitly supplied authority/coverage assertions, not inferred complete history.
- Backend configuration is explicit process environment, never dotenv: existing Supabase/ingestion credentials, which also configure the contextual reviewer (`REVIEW_ENDPOINT`/`REVIEW_MODEL`/`REVIEW_API_KEY` are optional overrides for reviewing on a different model or account); default rule generation additionally requires `JEV_API_KEY` and reuses the extractor's `HELMCODE_API_KEY`/`HELMCODE_BASE_URL`/`HELMCODE_DEEPSEEK_MODEL` for rule authoring (there is no separate DeepSeek key). `--ruleset PATH --rule-source NAME=PATH` pins an existing ruleset instead of regenerating it (or `REVISION_RULESET_PATH` plus JSON `REVISION_RULE_SOURCES`). `--status-key INTENT` retrieves a durable run without local PDFs; repeating an in-flight/unknown intent never automatically reissues paid work.
- Core/backend checks: `uv run --locked --extra worker --extra backend python -m pytest -q tests/decision_context/test_backend_engine.py tests/decision_context/test_core_engine.py tests/test_core_engine_review.py`. These use disposable local Postgres and mocked Supabase Storage/provider responses.
- Backend invoice discovery follows `backend.caja_paths.facturas()` unless `REVISION_INPUT_DIR`/`--input-dir` overrides it. Seed the live workbook with `make caja` when using the default `sources.yaml`, or supply an explicit mapping; never write to `caja_de_alberto/vN` snapshots.
- Contextual prompt v2 uses bounded, pointer-preserving evidence views only when the full request exceeds its budget. Full source artifacts and evaluations remain immutable; citations must match both originals and retained views. Projected reviews remain INCOMPLETE with attention required, even when the model supports every rule. Historical v1 full-request reviews remain readable.
- NIF/VAT capability regressions are in `tests/test_tax_rule_execution.py`: the configured NIF flag checks Spanish control characters, not registration; VAT checking covers one explicitly evidenced EUR VAT row with half-up cent rounding and policy tolerance, not legal rate eligibility or inferred multi-rate bases. Missing authority is never filled with defaults to obtain approval.
- Next-PR integration plans are `docs/frontend-engine-contract-next-pr.md` and `docs/full-engine-benchmark-next-pr.md`. Frontend/benchmark implementation and owner-managed live database migration are deliberately deferred, not implicitly completed by passing core contract tests.
